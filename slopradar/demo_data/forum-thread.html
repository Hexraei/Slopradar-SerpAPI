We tried it for API docs last quarter. Reference pages were fine because they're generated from the OpenAPI spec anyway. Tutorials were bad. It kept writing steps that looked right but skipped the auth header, so every example 401'd.

Same here. I use it to get a rough outline, then delete most of what it writes. The outline part is useful. The prose is not.

Our tech writer quit using it after it described a breaking change as a "seamless upgrade". That one made it into prod docs for a day and we got three support tickets.

Counterpoint: for translating our docs to German and Japanese it has been genuinely good, better than the agency we paid before. We still have native speakers review it but the review takes an hour instead of a week.

I mostly use it to write the boring parts: changelog entries, migration notes, the "requirements" section. Anything with an opinion I write myself. Honestly the biggest win was grep-style checks for words we banned from our docs, which doesn't need AI at all.

Does anyone have numbers on whether readers can tell? Our bounce rate didn't change when we swapped a few pages, but that's a small sample and we didn't control for anything.
